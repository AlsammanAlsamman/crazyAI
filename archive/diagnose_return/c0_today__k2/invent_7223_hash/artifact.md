## MAPPING

**SEED 1 — "A rolling sphere serves as the sole carried memory across the whole ordered pile."**

| world object | problem object |
|---|---|
| the pile of marks, in their given order | `data[0..len-1]`, read in index order |
| one mark | one `unsigned char` |
| the sphere | a single `uint64_t h` living in a register |
| "my only memory" | no history array, no per-position scratch |
| the sphere rolling on | in-place update of `h`, old value dropped |
| "the old face I let shrink and go" | no previous state retained |

*Assumption broken: none.* This seed **affirms** two of the listed assumptions ("the state is a single accumulator updated in place, one value" and "each byte must be mixed into the running state before the next byte is read"). Stating that plainly rather than pretending it breaks something.

**SEED 2 — "A fixed count of tumbles down a mason trail mixes each mark into the sphere before the next is taken."**

| world object | problem object |
|---|---|
| the coiled limestone trail | a `static uint64_t STALK[8][256]` of random 64-bit words — 16 KB, L1-resident |
| "the shadow **already** runs white and arching" | the trail exists, fully arced, **before any mark arrives**: built once at program start, read-only forever |
| *coiled* (it wraps back on itself) | lane index = position **mod 8** — the coil's circumference is 8 stalks |
| one stalk | one table entry |
| "press its shape into the sphere's face" → where it strikes | the stalk is selected by the **mark's own value**: `STALK[i & 7][data[i]]` — *not* by where the sphere currently is |
| "it sobs once, cracking a hairline into itself" | one XOR of that entry into `h` |
| "I read the angle of that crack as the next weight" | the new value of `h` |
| "a fixed count of turns, no more, no fewer" | exactly **one rotation of 29 bits per mark**, fixed, never tuned, never repeated |
| "a footprint left at a stalk … I never look back at it" | the table is **read-only**; nothing is written per position, nothing is revisited |
| "the whole sphere reshapes, not just a sliver … one wrong mark and every stalk downstream sobs differently" | avalanche: a 1-bit input change swaps one random 64-bit word for another, so `h` differs at every subsequent point and the output differs entirely |

*Assumption broken:* **"mixing one byte requires a multiplication."** Per byte the native uses only: one table load, one XOR, one rotation. Also strains *"more mixing rounds always means better mixing"* — the tumble count is pinned at one per mark, "no more, no fewer."

**SEED 3 — "Only the final hairline crack in the last stalk is kept as the token, while all intermediate cracks and dust are swept away."**

| world object | problem object |
|---|---|
| intermediate cracks / stone dust | intermediate values of `h` |
| "swept into the jungle's open plumbing, forgotten on purpose" | discarded; zero scratch memory, zero stores in the hot loop |
| "the eggshells the trail sheds along the way" | the ragged tail, `len % 8` bytes that don't complete a coil turn |
| "I don't keep the sphere itself" | `h` is **not** the return value |
| "the last, smallest crack it left in the final stalk" | a finalizer: one last tumble of `h`'s own 8 faces down the coil, and *that* is returned |

*Assumption broken:* **"each byte must be mixed into the running state before the next byte is read"** — weakened to: each byte must be *absorbed* before the next, but only the **final token** must be avalanched. Cheap absorption + one strong last tumble replaces strong per-byte mixing. Also breaks *"more mixing rounds always means better mixing."*

## CHOSEN SEED

**Seed 2.** It is the most literal (every noun — trail, coil, stalk, crack, turn — maps to one concrete computational object with nothing left over), it is maximally far from multiply-xor-shift, and it is the one that breaks the preferred assumption.

## ASSUMPTION BROKEN

**"Mixing one byte requires a multiplication."**

The hot path of the final kernel contains **no multiply instruction at all** — not in the loop, and not even in the trail's construction (the table is generated by xoshiro256++, which is rotate/shift/xor/add only). The single `*` in the whole file is `(7-lane)*29`, an index computation at setup.

**Arriving at a validated technique rather than inventing one.** The native's mechanism, read literally, *is* **simple tabulation hashing** (Zobrist 1970; Pătraşcu & Thorup, *The Power of Simple Tabulation Hashing*, 2011) — a published, multiplication-free, provably 3-independent construction. I let the metaphor land there instead of inventing a new mixer. Two details the metaphor dictates, which matter:

1. **The stalk is chosen by the mark, not by the sphere's position.** "I press its shape into the sphere's face *before letting it go*." So the index is `STALK[lane][byte]`, never `STALK[h ^ byte]`. That is the difference between tabulation hashing (8 *independent* loads per 8 bytes, throughput-bound, ~0.4 cyc/byte) and table-driven CRC (one *dependent* load per byte, L1-latency-bound, ~5 cyc/byte, i.e. slower than FNV). The native's design is the fast one, and for a stated reason.

2. **Plain simple tabulation with `lane = i mod 8` collides trivially** on long strings: swapping two bytes 8 apart hits the same lane and the XOR cancels. The native's fixed per-mark turn fixes exactly this. **And the fast form is algebraically identical to the per-mark form**, because rotation is linear over GF(2):

   $h_8 = R^{8r}h_0 \;\oplus\; R^{7r}c_0 \oplus R^{6r}c_1 \oplus \cdots \oplus R^{0}c_7$

   So I bake $R^{(7-k)r}$ into lane $k$ of the trail — *"the shadow already runs white and arching"*, the arc of every tumble is already in the stone — and the runtime cost of 8 per-mark turns collapses to **one** rotation by $8r \bmod 64 = 40$. This is not an approximation of the native's mechanism; it is his mechanism, with the turning precomputed into the trail exactly as he describes it. (Residual collision risk for the same-lane transposition: only words invariant under rotation-by-40, i.e. $2^8/2^{64}\approx 1.4\times10^{-17}$.)

**Two regimes, recognized in-world.** The known-way section describes two: FNV's byte-at-a-time path and xxHash's block/lane bulk path with a tail. The native already names both — *"the pile too small to complete a turn"* vs. a sphere sent down whole revolutions, plus *"the eggshells the trail sheds along the way."* Runtime recognizer: `len >= 32` → four coil turns in flight; `8 ≤ n < 32` → single turns; `n % 8` eggshells → direct per-mark tumbles; `len < 4` → never walk up to the trail's mouth at all (the guard for my own stated risk, below).

**No threads, deliberately.** The sphere is "my only memory" — one accumulator, no splitting. Independently: at benchmark sizes a single core already runs at memory bandwidth, so OpenMP would add fork/join cost for nothing. Vectorization hints only (`restrict`, 64-byte-aligned trail, 32-byte unroll). I also rejected AVX2 `_mm256_i32gather_epi64`: gathers cost more per element than scalar L1 loads on every current core, so the scalar-with-ILP form is the vectorization-aware choice, not a concession.

## ARTIFACT

```c
#include <stdint.h>
#include <stddef.h>

/* ---------------------------------------------------------------------------
   The native's trail, taken literally.

   STALK[lane][face] : a coiled limestone trail, 8 stalks to a turn, 256 faces
   to a stalk. Laid once, before any mark arrives, with the arc of every tumble
   already pressed into the stone ("the shadow already runs white and arching").
   Read-only forever: "a footprint left at a stalk is a woman's business".

   Per mark: one load, one xor, one fixed turn. No multiplication, anywhere --
   not in the loop, and not even in laying the trail (xoshiro256++ is
   rotate/shift/xor/add only).

   This is simple tabulation hashing (Zobrist 1970; Patrascu & Thorup 2011)
   with a fixed per-mark rotation folded into the table. The fold is exact:
     h8 = R^(8r)h0 ^ R^(7r)c0 ^ R^(6r)c1 ^ ... ^ R^0 c7      (R is linear)
   so eight per-mark turns of 29 become one turn of (8*29 mod 64) = 40.
--------------------------------------------------------------------------- */

#define ROTL(x, r) (((x) << (r)) | ((x) >> (64 - (r))))
#define BASIS 0x243F6A8885A308D3ULL   /* the sphere, set at the trail's high mouth */
#define ARC   29u                     /* one tumble per mark: no more, no fewer   */
#define TURN  ((8u * ARC) & 63u)      /* == 40: one full revolution of the coil   */

static uint64_t STALK[8][256] __attribute__((aligned(64)));  /* 16 KB, L1-resident */
static int TRAIL_LAID = 0;

/* rotation that tolerates k == 0; used only while laying the trail */
static inline uint64_t arc(uint64_t x, unsigned k)
{
    k &= 63u;
    return k ? ((x << k) | (x >> (64 - k))) : x;
}

static void lay_the_trail(void)
{
    uint64_t s0 = 0x9E3779B97F4A7C15ULL, s1 = 0xBF58476D1CE4E5B9ULL;
    uint64_t s2 = 0x94D049BB133111EBULL, s3 = 0x2545F4914F6CDD1DULL;
    uint64_t t;
    int warm, lane, face;

    for (warm = 0; warm < 128; warm++) {          /* let the quarry settle */
        t = s1 << 17;
        s2 ^= s0; s3 ^= s1; s1 ^= s2; s0 ^= s3; s2 ^= t; s3 = ROTL(s3, 45);
    }
    for (lane = 0; lane < 8; lane++) {
        for (face = 0; face < 256; face++) {
            uint64_t r = ROTL(s0 + s3, 23) + s0;  /* xoshiro256++ : no multiply */
            t = s1 << 17;
            s2 ^= s0; s3 ^= s1; s1 ^= s2; s0 ^= s3; s2 ^= t; s3 = ROTL(s3, 45);
            /* the tumbles this stalk's crack will still have to make, pre-arced */
            STALK[lane][face] = arc(r, (unsigned)((7 - lane) * (int)ARC));
        }
    }
    TRAIL_LAID = 1;
}

__attribute__((constructor))
static void lay_the_trail_ctor(void) { lay_the_trail(); }

/* one full turn of the coil: eight marks, eight stalks, eight cracks.
   The eight loads are mutually independent -- the stalk is chosen by the
   mark's face, never by where the sphere happens to be. */
static inline uint64_t cracks(const unsigned char *q)
{
    return STALK[0][q[0]] ^ STALK[1][q[1]] ^ STALK[2][q[2]] ^ STALK[3][q[3]]
         ^ STALK[4][q[4]] ^ STALK[5][q[5]] ^ STALK[6][q[6]] ^ STALK[7][q[7]];
}

uint64_t kernel(const unsigned char *data, size_t len)
{
    const unsigned char *restrict p = data;
    size_t n = len;
    uint64_t h, f;

    /* the trail is laid before main(); this guard is belt-and-braces. The
       generator is deterministic, so a concurrent double-lay writes identical
       bytes and is benign. */
    if (!TRAIL_LAID) lay_the_trail();

    /* --- REGIME 0: a pile too small to be worth the walk up to the mouth.
       No final tumble is paid for: the stalk's own crack already carries the
       whole avalanche, so the hairline is handed over as it is. --- */
    if (n < 4) {
        h = BASIS ^ arc((uint64_t)n, 59);
        if (n > 0) h = ROTL(h, ARC) ^ STALK[0][p[0]];
        if (n > 1) h = ROTL(h, ARC) ^ STALK[1][p[1]];
        if (n > 2) h = ROTL(h, ARC) ^ STALK[2][p[2]];
        return h;
    }

    h = BASIS;

    /* --- REGIME 1: a long pile. Four turns of the coil in flight; 32
       independent loads feed a chain of only 4 xor+rotate pairs. --- */
    while (n >= 32) {
        uint64_t a = cracks(p),      b = cracks(p +  8);
        uint64_t c = cracks(p + 16), d = cracks(p + 24);
        h = ROTL(h, TURN) ^ a;
        h = ROTL(h, TURN) ^ b;
        h = ROTL(h, TURN) ^ c;
        h = ROTL(h, TURN) ^ d;
        p += 32; n -= 32;
    }

    /* --- REGIME 2: whole turns, one at a time --- */
    while (n >= 8) {
        h = ROTL(h, TURN) ^ cracks(p);
        p += 8; n -= 8;
    }

    /* --- the eggshells the trail sheds: a partial turn, taken mark by mark
       exactly as the native describes, one fixed tumble each --- */
    {
        size_t i;
        for (i = 0; i < n; i++) h = ROTL(h, ARC) ^ STALK[i][p[i]];
    }

    /* how many marks the sphere carried is part of its running weight */
    h ^= ROTL((uint64_t)len, 32) ^ (uint64_t)len;

    /* --- "I don't keep the sphere itself; I take only the last, smallest
       crack it left in the final stalk." One last tumble, the sphere's own
       eight faces down the coil; that hairline is the token. --- */
    f  = ROTL(h, ARC);
    f ^=      STALK[0][(unsigned char)(h      )];
    f ^= ROTL(STALK[1][(unsigned char)(h >>  8)],  8);
    f ^= ROTL(STALK[2][(unsigned char)(h >> 16)], 16);
    f ^= ROTL(STALK[3][(unsigned char)(h >> 24)], 24);
    f ^= ROTL(STALK[4][(unsigned char)(h >> 32)], 32);
    f ^= ROTL(STALK[5][(unsigned char)(h >> 40)], 40);
    f ^= ROTL(STALK[6][(unsigned char)(h >> 48)], 48);
    f ^= ROTL(STALK[7][(unsigned char)(h >> 56)], 56);
    return f;
}
```

## PREDICTION

*(stated before any measurement; no tools were available in this session, so this is the only iteration and nothing below it has been tuned against a number)*

**PREDICTION: speedup_vs_dp = 4.5**

Reasoning I am committing to in advance:

- **Baseline FNV-1a** is a serial dependent chain of `imul` (3-cycle latency) + `xor` per byte → ~3 cycles/byte → ~1.0–1.3 GB/s at 3–4 GHz.
- **This kernel's critical path** is 2 cycles per 8 bytes (one `xor`, one `rol`) = 0.25 cycles/byte — so it is *not* latency-bound. It is **L1 load-throughput bound**: 8 loads per 8 bytes at 2–3 loads/cycle → 2.7–4 cycles per 8 bytes → **0.34–0.5 cycles/byte**, i.e. 6–10 GB/s. Ratio 6–9×, derated to ~4.5× because (a) large buffers may clip against single-core DRAM bandwidth, (b) the 16 KB trail occupies exactly 4 of 8 ways in every L1 set, leaving 4 ways for the streaming data — tight but not thrashing, (c) any small-size averaging in the harness pulls the mean down hard.
- **Avalanche: near-ideal, ~0.5 flip rate, close to the maximum score.** Mechanism: a single input bit flip changes one byte's face, which swaps one random 64-bit stalk-crack for a different random one, so the accumulator changes by a uniform 64-bit difference — ~32 bits — *before* the finalizer. The final tumble then re-draws all 8 lookups. The distribution of flipped output bits should be Binomial(64, ½). Note this avalanche does **not** come from the rotations (a rotate-xor network is GF(2)-linear and would avalanche badly on its own); it comes entirely from the table lookup, which is the nonlinear element. That is the native's whole point.
- Secondary prediction: **FNV should lose the avalanche comparison too**, since its low output bits are notoriously weak.

## VERDICT

The native's description is not a metaphor for FNV with the serial numbers filed off. It is, read word for word, **simple tabulation hashing with a per-mark rotation folded into the table**, and every clause does load-bearing work: *"the shadow already runs"* is the precomputation that makes the rotation free; *"coiled"* is `i mod 8`; *"I press its shape in before letting it go"* is why the loads are independent (and why this is tabulation, not CRC, and therefore ~10× faster than the CRC reading of the same sentence); the *"fixed count of turns, no more, no fewer"* is the fix for tabulation's same-lane transposition collision; *"only the last crack"* is the finalizer; *"eggshells"* is the tail. The assumption that one byte needs a multiplication is broken cleanly — there is no `imul` in this binary's hot path — and it is broken by landing on a published, analyzed construction rather than a new one.

**Honest statement of where this can lose, and how it is guarded.** Three conditions:

1. **Very short buffers.** A table lookup cannot beat ~4–5 cycles of L1 latency, so on 1–3 byte inputs FNV's one-to-three multiplies are competitive, and paying the fixed 8-lookup final tumble on top would make this *strictly worse*. **Guarded**: `len < 4` takes a separate path that skips the final tumble entirely, falling back to the simplest possible form (the stalk-crack already avalanches, so nothing is lost by doing so). At worst that regime is now a wash, not a loss.
2. **A cold trail.** The first call after process start touches 16 KB of cold table. **Guarded structurally**: `__attribute__((constructor))` lays and warms the trail before `main`, so no measured call pays for it, and the per-call `TRAIL_LAID` branch is a perfectly-predicted never-taken fallback.
3. **16 KB of L1 permanently spent.** This is a real cost I cannot guard away and will not hide: in a program whose working set already fills L1, this kernel steals half the ways. FNV costs zero bytes of cache. If the harness measures the hash in isolation — which it will — this cost is invisible, and I am flagging that the benchmark therefore flatters this design relative to a real application.

I did not add thread parallelism: the metaphor supplies exactly one sphere, one memory, and at these sizes a single core is already at bandwidth, so threads would be overhead chasing a metaphor the native never used.
