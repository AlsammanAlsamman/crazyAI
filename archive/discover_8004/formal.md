**The pattern underneath the telling:**

Two ordinary mechanisms are welded together, and the weld point is what makes the whole thing interesting.

**1. A synchronized global counter driving periodic re-binding.**
Take a set of elements (the doors) each holding a *relation* to some other element (which gangway each door faces) in a space that is independently and continuously drifting (the ships shifting on their moorings). Overlay a single shared counter, incremented by one whenever any instance of a defined event occurs anywhere in the system (a crown changing hands), with every copy of the counter kept identical at every location simultaneously — no local lag between instances. When the counter completes a fixed cycle (a modulus — "a full turn"), it fires a global recomputation: every element's relation is reset to whatever is *currently* nearest in the drifting space, then holds fixed until the next full cycle.

That much is a clean, formalizable structure: a modular counter as a synchronization clock, gating a periodic nearest-neighbor reassignment across a distributed set of bound pairs. It's the shape of things like: hash-table rehashing on load-factor threshold, a Lamport-clock-gated barrier, or a flock that re-orients to centroid every *N* ticks.

**2. A counter that can never equal its own true value.**
The second piece breaks that cleanliness on purpose. The event that increments the counter (the elephant taking a crown) is *always already moving toward the next increment* before the current one has finished propagating and triggering its consequence. So the counter is never in a settled, readable state — it is definitionally always one increment behind whatever has actually happened. This isn't ordinary latency (which resolves if you wait); it's stipulated as permanent: the count is always "owed" more than it shows, by construction, forever.

**Why it resists a single clean formal statement:**
A modular counter with a completion-triggered reset is fully formalizable on its own. A perpetual, unresolvable one-increment deficit is also nameable (an arrears, a running remainder that never zeroes, something like a series that never reaches its own limit). But *combining* them changes the character of the first: it's no longer "a clock that reaches N and fires" so much as "a clock that fires precisely because it can never be caught looking at N" — the trigger condition and the impossibility-of-settlement are the same fact stated twice. That's not a counter *plus* a lag term; the lag is doing the work the completion condition would normally do. I can describe that coupling, but I can't reduce it to one formula without either dropping the "always mid-motion" part (which is the actual point of the piece) or dropping the "discrete completed cycle" part (which is what makes it a *turn* rather than just drift). So: a real, describable two-part structure — synchronized modular reassignment + a built-in non-closing remainder — that doesn't collapse into fewer parts than that.
