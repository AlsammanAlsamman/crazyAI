**Where this structure genuinely lands, and where I think it doesn't:**

**1. Ice-core / varve / speleothem chronology — dating uncertainty near the base of a core.**
Real problem: annual-layer counting (the primary dating method for ice cores like EPICA Dome C, WAIS Divide, or laminated lake sediments) breaks down with depth because ice-flow thinning compresses each year's layer until it can no longer be distinguished from surrounding deformed material — chronology uncertainty grows nonlinearly and eventually becomes unresolvable well before bedrock.

How the structure applies, piece by piece: index = depth/year; raw input = that year's snowfall/isotope signal; the "resistance-dependent transformation" = compaction and diagenesis (some years compress cleanly, some don't); the recorded unit is genuinely category+magnitude (e.g., summer/winter layer, with thickness scaling accumulation rate); and — this is the load-bearing part — dating labs already use *redundant cross-channel encoding* exactly as described: the same annual boundary is read independently via dust bands, electrical conductivity (ECM), and δ18O, precisely because no single channel is trusted alone. The boundary-non-individuation clause maps onto the real, named failure mode: near the base, layers blend into the ambient ice matrix the same way the "ground" blends with the "figure" in the structure — it's not noise, it's a structural limit where the encoding motif and its substrate become the same vocabulary.

How to check it: this is directly testable against public data. Published age-uncertainty curves for existing cores show an inflection depth where uncertainty inflates sharply. The falsifiable claim: that inflection point should coincide with where the independent proxy channels (dust/ECM/isotope) stop agreeing with each other, not just with where any single channel gets noisy. That's a correlation you can compute from published core datasets without new fieldwork.

**2. Near-threshold signal/glitch classification (e.g., gravitational-wave transient detection, or any matched-filter detection problem with a known "impostor" population).**
Real problem: in LIGO/Virgo-style searches, weak real astrophysical signals near detection threshold and instrumental glitches (e.g. "blip" glitches) can produce nearly identical time-frequency templates — classifiers are currently forced into a binary signal/noise decision even in the region where the two populations are provably not separable by the features used.

The structure's contribution here is narrow but real: it names the boundary-non-individuation condition as a *first-class category*, not a confidence score to be minimized away. Applied concretely: instead of a binary classifier, output three states — "signal," "glitch," and "structurally indistinguishable at this SNR" — where that third state isn't a hedge but an explicit acknowledgment that the encoding vocabulary (template shape) is shared with the background at that regime, same as the rings-blending-with-substrate clause.

How to check it: use an existing labeled glitch catalog (e.g., Gravity Spy) plus injected-signal near-threshold trials. Compare calibration (reliability diagrams) of a three-way classifier against a forced binary one. If the "indistinguishable" bucket's boundary coincides with where the two populations' feature distributions actually overlap (measurable via e.g. Bhattacharyya distance), that's a concrete pass/fail test of whether the structural distinction is doing real work versus just relabeling low-confidence cases.

**What I won't force:** the "container, not message" functional-class distinction — the object built to be *occupied* rather than *decoded* — doesn't honestly transfer to either problem above, or to anything else I can name concretely. Every real candidate I considered (data structure placeholders, algebraic-type tags, git history squashing) required bending the container/signal distinction into something it wasn't built to say, rather than the domain actually needing that distinction to solve a problem. I'd rather flag that as a piece of the bundle that stayed poetic than manufacture a third application around it.
