STRUCTURE

Take a chain of finite counters L0, L1, L2, … , each Li a cyclic group Z/nᵢ (its own arbitrary modulus). A single external clock only ever ticks L0: add 1 to its value. Normal mixed-radix arithmetic stops there except for an upward carry — when Li overflows (wraps past nᵢ−1 back to 0), Li+1 is incremented by 1. This structure keeps that upward carry but adds a second, opposite one: every overflow at layer i also emits a *reflection pulse* downward, incrementing Li−1 by 1 (layer 0 has nowhere to reflect, so it absorbs silently). So a single tick can ripple two ways at once: up through carries, down through reflections, and those two waves can re-cross a layer that already changed this tick.

That crossing needs a collision rule, since a layer can receive an external tick, an upward carry, and a downward reflection in the same instant. Four natural choices: sum them (mod nᵢ), XOR them, take the max, or treat a collision itself as a fresh local overflow that emits its own pulses both ways — recursive interference rather than resolution. Which rule you pick changes the whole system's character: sum/mod gives a well-defined but chaotic-looking deterministic map; the recursive-collision rule can, for some modulus choices, fail to terminate within a tick (an internal echo that never damps), which is itself worth studying as a stability question — for which (n₀, n₁, …) and which collision rule does every tick provably terminate?

The object of interest isn't the final value at any layer but the *pulse trace*: which layers fired, in what order, for each external tick — a discrete, deterministic, layered interference pattern grown from the plainest possible input.

PROPOSALS

1. **Avalanche/mixing quality in lightweight checksums.** Ordinary mixed-radix counters (odometers) are linear and carry information in only one direction, so a single low-order change affects only nearby high-order digits predictably — this is exactly why raw counters make weak hash/checksum cores. Using the layered structure's sum-mod collision rule as a mixing step (feed input bytes as tick counts into L0, read the pulse trace or final layer values as output) should, if the reflection actually does anything, cause single-bit input changes to influence layers *both above and below* the initial disturbance, which a pure upward-carry counter cannot do. To check: implement both the standard odometer and the reflected version with matched moduli, run a standard avalanche test (flip one input bit, measure Hamming distance between output pulse traces over many random inputs), and compare the distribution to what plain carry propagation gives. If the reflected version doesn't beat the baseline avalanche numbers, the idea has failed honestly and that's a clean, useful negative result.

2. **Termination/stability boundary for the recursive-collision variant.** This is a self-contained combinatorics question the structure raises on its own, independent of any application: for a given tuple of moduli and the "collision reflects again" rule, does every single external tick always resolve in finitely many internal pulses, or can some modulus combinations produce an infinite internal echo? This is checkable directly by brute-force simulation across small modulus tuples (say all nᵢ ≤ 8, chains up to length 5), tracking whether any tick's internal pulse count exceeds a large cutoff, and then looking for a number-theoretic pattern (e.g., relation to gcd(nᵢ, nᵢ₊₁) or nᵢ, nᵢ₋₁) in which tuples terminate. No forced external motivation needed here — it's a legitimate open question generated by the structure itself, and a clean yes/no computational answer is available.

I don't have a third application I can honestly defend beyond speculation (a physics coupled-oscillator analogy occurred to me, but the correspondence would be cosmetic — discrete pulse reflection isn't actually equivalent to continuous phase coupling without contorting the mapping) — so I'm leaving it at two rather than manufacturing a connection.
