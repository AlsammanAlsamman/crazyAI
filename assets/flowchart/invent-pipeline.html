The matmul-specific measure step, zoomed in

This is the step worth understanding before changing anything — it's the only place a "crazy" idea meets a compiler and a clock, and it's where the batch's three compile errors and the cross-machine GFLOP/s trap both live.

exact formulas, from kernel.py / invent.py
value
speedup_vs_blocked × exactness, at the largest size measured (n = 512 by default — never 1024, the size the lab's own comparisons use)
calibration
1 − |prediction − value| ⁄ max(prediction, value) — how close the engineer's own guess was
discovery
value × (0.5 + 0.5 × imagination_score) — what invent-rank sorts by

Where to improve it

Five concrete openings, found running the first real 10-seed batch end to end.

step 06 · MEASURE

Default sizes are [64, 256, 512], hardcoded in step_measure — every invent run is judged on matrix sizes well under the n = 1024 this project's own comparisons use.

Fix: make sizes a CLI flag, default to include 1024.

step 06 · MEASURE

The blocked reference kernel is single-threaded C; AI-written kernels routinely add #pragma omp. value and discovery then reward "used more cores," not "smarter algorithm."

Fix: parallelize the blocked baseline too, or report both a 1-thread and all-core ratio.

every step · ranking

GFLOP/s and value aren't portable across machines — this session nearly reported a 24-core desktop's numbers as if comparable to the original 4-core laptop's.

Fix: have step_archive capture one real OpenBLAS number for the current machine once, store it alongside every run.

step 02 · HARVEST

A parse failure (no [...] match, bad JSON) silently becomes 0 fragments — happened on seed 1 of the batch with no error surfaced, only a low count in the log.

Fix: log the raw response on a parse miss instead of swallowing it.

step 05→06 · BEND → MEASURE

3 of the batch's 10 seeds ended in COMPILE_ERROR with no repair attempt, even though the bend prompt already tells the model to "measure and improve it up to four times."

Fix: check whether that in-bend loop is actually firing on a compiler error, not just a bad speedup.
